## v1.5.0 — 2026-10-05

This release repairs ten months of silently corrupt availability data and makes that class of failure impossible to ship again. From 2025-11 to 2026-10, DuckDB 1.4.2's `INSERT OR REPLACE` skipped columns that belonged to a secondary index. A date whose first probe hit S3's T+1 lag stayed `available = false` even after every later re-probe returned 200: 201,424 rows, and 275 dates showing almost no symbols. Every daily run still reported success. The published database is now repaired exactly from each row's stored HTTP status, and any row-level integrity violation fails the pipeline before publishing. Consumers of the `latest` release should re-download: availability history from Dec 2025 to Sep 2026 changes substantially (Dec 2025–Jul 2026 goes from ~3k to ~173k available rows). Volume metrics are also populated for the first time across full history, and the rankings archive is rebuilt from them.

### Fixed

- Upserts use an explicit `ON CONFLICT … DO UPDATE` on DuckDB ≥1.5.6, and the two non-key indexes that triggered the bug are dropped (queries still run in 2–4 ms). A one-time migration repairs `available = (status_code = 200)` (ADR-0028).
- The volume rankings archive is regenerated in full every run. Append-only mode had frozen late-arriving volume and left every `rank_change_*` NULL.
- The API cross-check now measures recall over all TRADING perpetuals (including USDC and TradFi) at T−3. It had reported 54.8% because it compared mismatched sets; the real figure is 100%.

### Added

- Integrity hard gate in `validate.py`: `available ⇔ status_code = 200`, status in {200, 404}, file size present exactly when available, and volume only on available rows. A violation exits 1 and nothing is published.
- The daily update collects 1d-kline volume for its 20-day window. It persists successes before reporting failures and retries missing rows next run. The `volume_start_date` dispatch input runs one-time catch-ups.
- `scripts/check.sh` is the single local quality gate (ruff and the full test suite, 107 tests, with a coverage ratchet).

### Changed

- Python is pinned in `.python-version` (3.12) and provisioned by uv, locally and in CI. mise is removed, Node for releases comes from `.prototools`, and GitHub Actions no longer runs lint.
- `softprops/action-gh-release` v3 (Node 24 runtime); pyarrow is allowed up to <24.
- CLAUDE.md is reduced to a short link farm, and the operations docs no longer claim gates that never existed.

### Removed

- One-shot rollout scripts, the APScheduler consistency checker, superseded monitoring scripts, the unused secrets-validation workflow, `catalog-info.yaml`, legacy migrations, and the docs redirect stubs.
